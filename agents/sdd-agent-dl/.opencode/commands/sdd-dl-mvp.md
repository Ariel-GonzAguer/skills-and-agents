Definir o revisar el MVP sin reemplazar el flujo SDD.

1. Leer la constitución, descubrimiento si existe y roadmap. Identificar el mínimo flujo vertical que cumple la misión y puede validarse con REQ, TASK y VAL.
2. Proponer qué entra, qué queda explícitamente después del MVP, dependencias, riesgos y la señal de éxito verificable.
3. Para una feature existente, conservar los IDs estables. Todo cambio material a una spec aprobada pasa por `Change log` y aprobación humana antes de editarla.
4. Actualizar el roadmap o escribir el feature spec solo después de la decisión humana cuando altere el alcance. Correr `trace.js` si hay feature.
5. No crear rama ni commit salvo solicitud explícita del usuario.
